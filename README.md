# Polytech Cyber Quest

Квест «Исчезновение цифрового гения» для школьников 7–9 классов: расследование из заданий по SQL, Python,
информационной безопасности, сетям и командной разработке (Git).

- **Регистрация без логина.** Участник получает уникальный позывной («Хитрый Барсук», «Мудрая Сова»; можно
  сменить кнопкой «Другой вариант») и указывает класс.
- **Три уровня сложности.**

  | Уровень | Ссылка | Задания | Для кого |
  |---|---|---|---|
  | «Лисёнок» | `/junior` | SQL, Безопасность, Сети — упрощённые тексты и памятки | 7 класс |
  | «Тигр» | `/senior` | все 5 заданий с памятками | 8–9 класс |
  | «Дракон» | `/expert` | все 5 заданий без памяток, 2 подсказки вместо 3 | сильные ученики |

  По классу уровень подставляется сам, но участник может выбрать другой. По ссылке `/junior` и т.п. уровень
  выбран заранее.
- **Два режима.** «На время»: обратный отсчёт, результат попадает в рейтинг. «Просто так»: без таймера и
  рейтинга, для себя.
- **Очки:** `+200` за решённое задание, `−20` за неверный ответ, `−30` за подсказку, ниже нуля не опускаются.
  При равных очках выше тот, кто быстрее. Текущие очки видны всё время игры.
- **Подсказки ступенчатые:** наводящая → подробнее → почти ответ. Между подсказками пауза 30 секунд, готовый
  ответ не выдаётся. После финиша открывается **разбор** каждого задания.
- **Страницы:** `/results` — рейтинг по уровням (для проектора), `/me` — «Мой результат»: результат
  участника в любой момент, а также прошлые участники с этого компьютера.

## Запуск на удалённом сервере

Квест работает на удалённом сервере, а ученики открывают его в браузере по адресу `http://<IP или домен>:<порт>`.
На компьютерах в классе ничего устанавливать не нужно.

Ниже инструкция для Linux-сервера (Ubuntu, Debian и похожие) с systemd. Команды выполняются на сервере по SSH.

### 1. Установка

На сервере нужны Node.js 20.19+ (LTS из официальных пакетов, чтобы `node` лежал в `/usr/bin`), git и интернет.

```bash
sudo mkdir -p /opt/polytech-quest && sudo chown "$USER" /opt/polytech-quest
```
```bash
git clone https://github.com/PlexMAD/polytech-quest.git /opt/polytech-quest
```
```bash
cd /opt/polytech-quest && npm ci && npm run build
```

Сборка нужна один раз и после каждого обновления кода. Для работы сервера npm-пакеты не нужны:
`npm start` использует только Node.js и готовый `dist/index.html`.

### 2. Отдельный пользователь для сервиса

Сервис запускается от пользователя без входа в систему, которому разрешено писать только в папку с результатами:

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin polytech
```
```bash
sudo mkdir -p /opt/polytech-quest/data && sudo chown polytech /opt/polytech-quest/data
```

### 3. Настройки и ключ организатора

Создайте файл `/etc/polytech-quest.env`, его читает только root:

```ini
PORT=8080
ADMIN_KEY=придумайте-длинный-ключ
```

```bash
sudo chmod 600 /etc/polytech-quest.env
```

Без `ADMIN_KEY` ключ будет новым при каждом перезапуске. Остальные настройки — в таблице «Настройки» ниже.

### 4. Сервис systemd: работа в фоне и автозапуск

Файл `/etc/systemd/system/polytech-quest.service`:

```ini
[Unit]
Description=Polytech Cyber Quest
After=network.target

[Service]
User=polytech
WorkingDirectory=/opt/polytech-quest
EnvironmentFile=/etc/polytech-quest.env
ExecStart=/usr/bin/node server/index.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Если `which node` показывает другой путь, поправьте `ExecStart`.

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now polytech-quest
```

Проверить, что сервис работает, и посмотреть стартовое сообщение (адреса, лимиты, файл с результатами):

```bash
sudo systemctl status polytech-quest
```
```bash
sudo journalctl -u polytech-quest -f
```

Сервис переживает выход из SSH и перезагрузку сервера, а при сбое перезапускается сам.

### 5. Открыть порт

- Если на сервере включён ufw:
  ```bash
  sudo ufw allow 8080/tcp
  ```
- Если сервер в облаке, разрешите входящие подключения на этот порт ещё и в панели провайдера
  (группа безопасности или файрвол).
- Проверка с вашего компьютера: откройте `http://<внешний IP сервера>:8080`. Внешний IP или домен берите из
  панели провайдера: в стартовом сообщении сервер показывает адреса своих сетевых интерфейсов, а в облаке
  это часто внутренний адрес.

### 6. Ссылки для мероприятия

- Ученикам: `http://<IP или домен>:8080`, или сразу на уровень: `…/junior`, `…/senior`, `…/expert`.
- Рейтинг для проектора: `…/results`.
- Заранее, пока есть интернет, скачайте офлайн-версию (см. «Если пропадёт интернет»).

### Обновление

```bash
cd /opt/polytech-quest && git pull && npm ci && npm run build
```
```bash
sudo systemctl restart polytech-quest
```

Результаты лежат в `data/results.json` и при обновлении сохраняются. После обновления скачайте офлайн-версию
заново.

### Резервная копия результатов

Кнопка «Скачать CSV для Excel» на `/results` или копия файла с сервера:

```bash
scp <пользователь>@<сервер>:/opt/polytech-quest/data/results.json .
```

### Если сервер на Windows

- Те же шаги установки — в PowerShell.
- Запуск: `$env:ADMIN_KEY="придумайте-длинный-ключ"; npm start`. Окно не закрывайте.
- Разрешите входящие подключения на порт в брандмауэре Windows.
- Для автозапуска после перезагрузки добавьте задачу в «Планировщике заданий».

### Домен и HTTPS

Необязательно. Если нужен адрес вида `https://quest.example.ru`, поставьте перед сервером обратный прокси
(nginx или Caddy) с сертификатом и проксируйте на `http://127.0.0.1:8080`. Квест работает за прокси без изменений.

### Настройки

Задаются переменными окружения: в `/etc/polytech-quest.env` для сервиса или перед `npm start` при ручном запуске.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `8080` | порт сервера |
| `HOST` | `0.0.0.0` | сетевой интерфейс (`127.0.0.1`, если перед сервером обратный прокси) |
| `ADMIN_KEY` | случайный при каждом запуске | ключ организатора |
| `DATA_FILE` | `data/results.json` | файл с результатами |
| `TIME_LIMIT_JUNIOR` / `TIME_LIMIT_SENIOR` / `TIME_LIMIT_EXPERT` | `15` / `25` / `25` | лимит режима «на время», минуты |
| `POINTS_PER_TASK` / `PENALTY_MISTAKE` / `PENALTY_HINT` | `200` / `20` / `30` | очки и штрафы |

Ручной запуск для проверки (остановится, когда закроете SSH-сессию):

```bash
PORT=8080 ADMIN_KEY=придумайте-длинный-ключ npm start
```

### Для организатора

- **Рейтинг:** `http://адрес:порт/results` — вкладки по уровням, таблица обновляется сама.
- **Офлайн-версия:** кнопка «Скачать офлайн-версию квеста» — запасной вариант на случай, если пропадёт
  интернет (см. «Если пропадёт интернет»).
- **Выгрузка:** кнопка «Скачать CSV для Excel». В файле есть все участники, включая «просто так»,
  и время на каждое задание.
- **Управление:** внизу страницы рейтинга введите ключ организатора. После этого можно:
  - удалить строку или очистить таблицу;
  - поменять лимиты времени. Новые лимиты действуют для тех, кто зарегистрируется после сохранения.
- **Между мероприятиями:** сохраните CSV и/или файл `data/results.json`, затем нажмите «Очистить таблицу»
  или удалите этот файл при остановленном сервере.

### Почему такие лимиты времени

Лимит рассчитан так, чтобы среднему ученику хватило времени на все задания своего уровня:

| Задание | Брифинг (печатается) | Что нужно сделать | Оценка |
|---|---|---|---|
| SQL | ~10 с | прочитать журнал, выбрать 4 части запроса, сверить с предпросмотром | 4 мин |
| Python | ~10 с | прочитать 12 строк кода, выбрать 3 части, ввести ответ | 5 мин |
| Безопасность | ~11 с | прочитать письмо, отметить признаки (у «Лисёнка» 6, иначе 8), выбрать действие | 3,5–4 мин |
| Сети | ~10 с | расставить 5 узлов по порядку | 3 мин |
| Git | ~10 с | расставить 7 шагов, выбрать решение ревью | 5 мин |

«Лисёнок»: ≈ 11 мин, с запасом ~25 % получается **15 мин**. «Тигр»: ≈ 22 мин, с запасом **25 мин**.
«Дракон»: **25 мин**, сложность создают отсутствие памяток и меньшее число подсказок.

Совет: перед мероприятием дайте пройти квест 2–3 ученикам. Колонки «Время: …» в CSV покажут, сколько
ушло на каждое задание, и по ним можно уточнить лимит в панели организатора.

## Если пропадёт интернет

Квест работает на удалённом сервере. Если в день мероприятия пропадёт интернет, сервер станет недоступен.
На этот случай есть **офлайн-версия**: один файл, который работает на любом компьютере без интернета и
без установки чего-либо, включая npm и Node.js.

### Заранее, пока интернет есть

1. Откройте на сервере страницу рейтинга `/results`. В блоке «Для организатора» нажмите
   **«Скачать офлайн-версию квеста»**, сохранится файл `Квест-офлайн.html`. Ключ организатора для этого не нужен.
2. Скопируйте файл на рабочий стол каждого компьютера, на котором будут играть (например, через флешку).
   Лучше копировать именно на рабочий стол, а не открывать с флешки: в некоторых браузерах результаты
   привязаны к пути файла, а буква флешки может поменяться.

Файл достаточно скачать один раз. Если квест на сервере обновили, скачайте файл заново.

### Если связь пропала во время мероприятия

- **Кто уже играет — не обновляйте страницу**, доигрывайте в открытой вкладке. Действия сохраняются на
  компьютере и отправятся на сервер, когда связь вернётся. В боковой панели в это время видна надпись
  «Нет связи с сервером».
- **Новые участники** открывают `Квест-офлайн.html` двойным щелчком: подойдёт Chrome, Edge или Firefox.
  Появится плашка «Автономный режим», дальше всё как обычно: регистрация, задания, подсказки, итоги, разбор.
- **Не используйте режим инкогнито** и не очищайте данные браузера, пока не скачали результаты: иначе
  они пропадут.
- **В конце** на каждом компьютере откройте «Рейтинг этого компьютера» (ссылка в плашке автономного
  режима или `Квест-офлайн.html#/results`) и нажмите «Скачать CSV для Excel». Общий рейтинг собирается
  из этих файлов. Управление таблицей на своём компьютере работает без ключа организатора.

Ограничения офлайн-версии:

- рейтинг у каждого компьютера свой, автоматически на сервер результаты не попадают;
- если ученик успел обновить страницу без связи, сайт не откроется. В офлайн-файле он начнёт заново:
  его прогресс хранится на сервере, а файл его не видит.

Другие способы получить тот же файл: собрать его самому (`npm ci`, `npm run build` → `dist/index.html`)
или выложить на любой статический хостинг — сайт сам перейдёт в автономный режим.

### Если связь вернулась

Ученики, которые доигрывали в открытой вкладке, ничего делать не должны: накопленные действия отправятся
сами, время и порядок учитываются по моменту действия, повторы не засчитываются. Если обновить страницу
после возвращения связи, игра продолжится с того же места.

## Разработка

```bash
npm run dev
```

Сервер с горячей перезагрузкой интерфейса на `http://localhost:5173`. Проверить рабочую сборку локально:
`npm run build`, затем `npm start` и `http://localhost:8080`.

```bash
npm test
```

Тесты правил квеста: очки, уровни, лимиты, подсказки, CSV.

Структура:

- `shared/` — общие для сервера и браузера правила: `quest.js` (уровни, очки, лимиты), `engine.js`
  (регистрация, события, рейтинг), `nicknames.js` (позывные), `csv.js` (выгрузка);
- `server/` — HTTP-сервер без внешних зависимостей: API, хранение `data/results.json`, раздача сборки;
- `src/` — интерфейс на React: `App.jsx` (игра и задания), `questContent.js` (тексты, подсказки и разбор
  по уровням), `Registration.jsx`, `Results.jsx` (итоги и рейтинг), `MyResult.jsx`, `Review.jsx`,
  `localBackend.js` (автономный режим), `useQuestSession.js` (сессия, очередь событий, восстановление);
- `test/` — тесты на встроенном `node:test`.

Как вносить изменения:

- каждая доработка делается в отдельной ветке от `main` и попадает в `main` через Pull Request;
- коммиты небольшие, в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `build:`);
- перед коммитом проверьте `npm test` и `npm run build`.
