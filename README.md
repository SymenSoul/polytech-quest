# Polytech Cyber Quest

Квест «Исчезновение цифрового гения» для школьников 7–9 классов: расследование из заданий по SQL, Python,
информационной безопасности, сетям и командной разработке (Git).

- **Регистрация без логина.** Участник получает уникальный позывной («Хитрый Барсук», «Мудрая Сова»; можно
  сменить кнопкой «Другой вариант») и указывает класс.
- **Три уровня сложности.**

  | Уровень | Ссылка | Задания | Для кого |
  |---|---|---|---|
  | «Лисёнок» | `/junior` | SQL, Безопасность, Сети — упрощённые тексты и памятки | 7 класс |
  | «Тигр» | `/senior` | все 5 заданий с памятками | 8–9 класс |
  | «Дракон» | `/expert` | все 5 заданий без памяток, 2 подсказки вместо 3 | сильные ученики |

  По классу уровень подставляется сам, но участник может выбрать другой. По ссылке `/junior` и т.п. уровень
  выбран заранее.
- **Два режима.** «На время»: обратный отсчёт, результат попадает в рейтинг. «Просто так»: без таймера и
  рейтинга, для себя.
- **Очки:** `+200` за решённое задание, `−20` за неверный ответ, `−30` за подсказку, ниже нуля не опускаются.
  При равных очках выше тот, кто быстрее. Текущие очки видны всё время игры.
- **Подсказки ступенчатые:** наводящая → подробнее → почти ответ. Между подсказками пауза 30 секунд, готовый
  ответ не выдаётся. После финиша открывается **разбор** каждого задания.
- **Страницы:** `/results` — рейтинг по уровням (для проектора), `/me` — «Мой результат»: результат
  участника в любой момент, а также прошлые участники с этого компьютера.

## Запуск на сервере для класса

Подойдёт любой компьютер (Windows, macOS, Linux) в одной сети с компьютерами учеников.

1. Установите Node.js 20 или новее: <https://nodejs.org> (версия LTS).
2. Скачайте проект и откройте папку в терминале (Windows: PowerShell или «Командная строка»).
3. Установите зависимости и соберите сайт (нужно один раз и после каждого обновления кода):
   ```bash
   npm ci
   npm run build
   ```
4. Запустите сервер:
   ```bash
   npm start
   ```
   В консоли появятся адреса вида `http://192.168.1.10:8080`, лимиты времени, ссылка на рейтинг
   и **ключ организатора**.
5. Ученики открывают этот адрес в браузере. Можно сразу дать ссылку на уровень: `http://192.168.1.10:8080/junior`.
6. Если ученики не могут подключиться:
   - Windows при первом запуске спросит про доступ Node.js к сети: разрешите доступ для частных сетей;
   - компьютеры должны быть в одной сети (гостевой Wi-Fi часто изолирует устройства друг от друга);
   - проверьте, что адрес набран с портом, например `:8080`.

Не закрывайте окно с сервером до конца мероприятия. Остановить сервер — `Ctrl+C`, результаты при этом
сохраняются.

### Настройки

Задаются переменными окружения перед `npm start`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `8080` | порт сервера |
| `HOST` | `0.0.0.0` | сетевой интерфейс |
| `ADMIN_KEY` | случайный при каждом запуске | ключ организатора |
| `DATA_FILE` | `data/results.json` | файл с результатами |
| `TIME_LIMIT_JUNIOR` / `TIME_LIMIT_SENIOR` / `TIME_LIMIT_EXPERT` | `15` / `25` / `25` | лимит режима «на время», минуты |
| `POINTS_PER_TASK` / `PENALTY_MISTAKE` / `PENALTY_HINT` | `200` / `20` / `30` | очки и штрафы |

```bash
PORT=3000 ADMIN_KEY=olymp2026 npm start
```

Windows PowerShell:

```powershell
$env:PORT=3000; $env:ADMIN_KEY="olymp2026"; npm start
```

Windows «Командная строка» (cmd):

```bat
set "PORT=3000" && set "ADMIN_KEY=olymp2026" && npm start
```

### Для организатора

- **Рейтинг:** `http://адрес:порт/results` — вкладки по уровням, таблица обновляется сама.
- **Выгрузка:** кнопка «Скачать CSV для Excel». В файле есть все участники, включая «просто так»,
  и время на каждое задание.
- **Управление:** внизу страницы рейтинга введите ключ организатора. После этого можно:
  - удалить строку или очистить таблицу;
  - поменять лимиты времени. Новые лимиты действуют для тех, кто зарегистрируется после сохранения.
- **Между мероприятиями:** сохраните CSV и/или файл `data/results.json`, затем нажмите «Очистить таблицу»
  или удалите этот файл при остановленном сервере.

### Почему такие лимиты времени

Лимит рассчитан так, чтобы среднему ученику хватило времени на все задания своего уровня:

| Задание | Брифинг (печатается) | Что нужно сделать | Оценка |
|---|---|---|---|
| SQL | ~10 с | прочитать журнал, выбрать 4 части запроса, сверить с предпросмотром | 4 мин |
| Python | ~10 с | прочитать 12 строк кода, выбрать 3 части, ввести ответ | 5 мин |
| Безопасность | ~11 с | прочитать письмо, отметить признаки (у «Лисёнка» 6, иначе 8), выбрать действие | 3,5–4 мин |
| Сети | ~10 с | расставить 5 узлов по порядку | 3 мин |
| Git | ~10 с | расставить 7 шагов, выбрать решение ревью | 5 мин |

«Лисёнок»: ≈ 11 мин, с запасом ~25 % получается **15 мин**. «Тигр»: ≈ 22 мин, с запасом **25 мин**.
«Дракон»: **25 мин**, сложность создают отсутствие памяток и меньшее число подсказок.

Совет: перед мероприятием дайте пройти квест 2–3 ученикам. Колонки «Время: …» в CSV покажут, сколько
ушло на каждое задание, и по ним можно уточнить лимит в панели организатора.

## Запуск без сервера (ноутбук, флешка)

Сайт работает и как один файл, без Node.js и сервера.

1. На компьютере с Node.js один раз выполните `npm ci` и `npm run build`.
2. Скопируйте файл `dist/index.html` на ноутбук (например, через флешку).
3. Откройте его двойным щелчком в Chrome, Edge или Firefox. Появится плашка «Автономный режим».

В автономном режиме:

- результаты хранятся в этом браузере на этом компьютере;
- рейтинг — по адресу `index.html#/results`, «Мой результат» — `index.html#/me`, ссылки на уровни —
  `index.html#/junior` и т.д.;
- выгрузка CSV и управление таблицей работают без ключа организатора;
- **не используйте режим инкогнито** и не очищайте данные браузера, пока не скачали CSV: иначе результаты пропадут;
- у каждого ноутбука своя таблица; общий рейтинг потом можно собрать из CSV.

Тот же `dist/index.html` можно выложить на любой статический хостинг: сайт сам перейдёт в автономный режим.

Чтобы играть с сервером на одном ноутбуке: `npm start` и откройте `http://localhost:8080`.

## Если сервер упал

- Пока страница открыта, игра продолжается. Действия копятся на компьютере ученика и отправляются,
  когда сервер вернётся; в боковой панели видна надпись «Нет связи с сервером».
- Обновить страницу, пока сервер выключен, нельзя: её отдаёт тот же сервер.
- После перезапуска сервера (`npm start`) ученик обновляет страницу и продолжает с того же места. Время
  и порядок действий учитываются честно, повторы не засчитываются.
- Если сервер недоступен в момент регистрации, участник регистрируется в автономном режиме на этом компьютере.

## Разработка

```bash
npm run dev
```

Сервер с горячей перезагрузкой интерфейса на `http://localhost:5173`.

```bash
npm test
```

Тесты правил квеста: очки, уровни, лимиты, подсказки, CSV.

Структура:

- `shared/` — общие для сервера и браузера правила: `quest.js` (уровни, очки, лимиты), `engine.js`
  (регистрация, события, рейтинг), `nicknames.js` (позывные), `csv.js` (выгрузка);
- `server/` — HTTP-сервер без внешних зависимостей: API, хранение `data/results.json`, раздача сборки;
- `src/` — интерфейс на React: `App.jsx` (игра и задания), `questContent.js` (тексты, подсказки и разбор
  по уровням), `Registration.jsx`, `Results.jsx` (итоги и рейтинг), `MyResult.jsx`, `Review.jsx`,
  `localBackend.js` (автономный режим), `useQuestSession.js` (сессия, очередь событий, восстановление);
- `test/` — тесты на встроенном `node:test`.

Как вносить изменения:

- каждая доработка делается в отдельной ветке от `main` и попадает в `main` через Pull Request;
- коммиты небольшие, в стиле Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `build:`);
- перед коммитом проверьте `npm test` и `npm run build`.
