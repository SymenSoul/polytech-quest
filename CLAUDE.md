# CLAUDE.md

Контекст для Claude Code и людей, работающих с этим репозиторием. Подробности для организаторов — в `README.md`.

## Проект

Веб-квест «Исчезновение цифрового гения» для школьного мероприятия: 7–9 классы, до ~30 участников, 5 заданий
(SQL, Python, Безопасность, Сети, Git). Квест работает на удалённом сервере, ученики открывают `http://IP:порт`
с компьютеров в классе (Windows 10/11).

**В классе может внезапно пропасть интернет**, а ставить там npm-пакеты и Node.js нельзя. Поэтому:
- в рабочем режиме серверу не нужны npm-зависимости;
- сборка — один самодостаточный HTML-файл, который работает и без сервера.

## Команды

```bash
npm ci          # зависимости (нужны только для сборки и разработки)
npm run dev     # сервер + Vite middleware с HMR, http://localhost:5173
npm test        # тесты движка (node:test), без внешних фреймворков
npm run build   # dist/index.html — один файл, JS и CSS встроены
npm start       # рабочий режим: 0.0.0.0:8080, раздаёт dist/ и API
```

Переменные окружения: `PORT`, `HOST`, `ADMIN_KEY`, `DATA_FILE`, `TIME_LIMIT_JUNIOR|SENIOR|EXPERT`,
`POINTS_PER_TASK`, `PENALTY_MISTAKE`, `PENALTY_HINT` (см. README).

## Архитектура

- `shared/` — **единственный источник правил**, общий для сервера и браузера. Чистый JS без Node API:
  случайные числа через `globalThis.crypto`.
  - `quest.js` — этапы (`MODULE_IDS`), уровни (`LEVELS`), режимы, очки (`computeScore`), лимиты, подсказки,
    `plural`, `formatDuration`;
  - `engine.js` — `createPlayer`, `applyEvent`, `summarize`, `buildLeaderboard`;
  - `csv.js` — выгрузка для Excel: BOM, `;`, защита от формул;
  - `nicknames.js` — словарь позывных.
- `server/` — HTTP на встроенных модулях Node, **без runtime-зависимостей**. `vite` подгружается только
  при `--dev`.
  - `store.js` — данные в памяти с атомарной записью в `data/results.json`;
  - `api.js` — маршруты: `/api/config`, `nickname`, `register`, `session`, `events`, `leaderboard`,
    `results.csv`, `admin/check`, `PUT settings`, `DELETE players[/:id]`;
  - `index.js` — раздача `dist/`, SPA-fallback, `/api/offline` (скачивание офлайн-версии).
- `src/` — React 19 + Vite 7, иконки `lucide-react`.
  - `App.jsx` — игра и 5 компонентов заданий;
  - `questContent.js` — все тексты по уровням: сюжет, подсказки, памятки, разбор;
  - `useQuestSession.js` — сессия, очередь событий, копия сессии в localStorage;
  - `api.js` — `request()` направляет вызовы на сервер или в `localBackend.js` (автономный режим, база
    в localStorage);
  - `Registration.jsx`, `Results.jsx` (итоги и `/results`), `MyResult.jsx` (`/me`), `Review.jsx` (разбор),
    `routes.js` (пути `/results` и hash `#/results`).
- `vite.config.js` — плагин `inlineAssets` встраивает JS и CSS в `dist/index.html`: по `file://` браузеры
  не грузят module-скрипты из отдельных файлов.

## Инварианты (не ломать)

- Порядок `modules` в `src/App.jsx` совпадает с `MODULE_IDS` (при расхождении бросается ошибка при загрузке).
  Этапы уровня берутся из `LEVELS[level].modules`.
- Логику очков, событий и рейтинга менять **только в `shared/`** и сопровождать тестами в
  `test/engine.test.js`. Не дублировать её в `src/` или `server/`.
- События идемпотентны по `eventId`. Время считается по `at` (момент действия, не позже «сейчас»), поэтому
  события, отправленные после обрыва связи, учитываются честно. После дедлайна события не принимаются.
- Лимит времени фиксируется у игрока при регистрации (`timeLimitMs`). Паузу между подсказками (30 с)
  проверяет и сервер (`lastHintAt`).
- Старые записи: без `level` → `senior`, без `mode` → `timed` без лимита.
- `dist/index.html` должен оставаться **одним файлом** и работать по `file://` и со статического хостинга
  (ссылки там строятся через `routeHref()` → `#/…`).
- `crypto.randomUUID` недоступен по `http://ip:порт` (не «безопасный контекст») — использовать `randomId()`
  из `src/api.js`.
- Тексты интерфейса и комментарии — на русском. Тексты для «Лисёнка» (7 класс) — без жаргона.

## Решения, согласованные с заказчиком (не пересматривать без запроса)

- Вход без логина: уникальный позывной из словаря без обидных слов + обязательный класс (7/8/9, буква по
  желанию). Имя не спрашиваем.
- Уровни: «Лисёнок» (`/junior`: SQL, Безопасность, Сети, упрощённо), «Тигр» (`/senior`: все 5),
  «Дракон» (`/expert`: без памяток, 2 подсказки).
- Режим выбирает участник: «на время» (в рейтинге) или «просто так» (без рейтинга).
- Лимиты 15 / 25 / 25 мин — рассчитаны по объёму заданий (таблица в README), организатор меняет их на `/results`.
- Очки: `+200` за задание, `−20` за ошибку, `−30` за подсказку, не ниже 0; при равенстве выше более быстрый.
- Подсказки: 3 ступени (наводящая → подробнее → почти ответ), готовый ответ не выдаётся.
- Запасной вариант без интернета — **только офлайн-файл** (кнопка на `/results`). Локальный сервер
  с флешки и импорт офлайн-результатов на сервер сознательно не делали.
- Известные ограничения: ответы проверяются в браузере; офлайн-рейтинг у каждого компьютера свой.

## Проверка изменений

- Перед коммитом: `npm test` и `npm run build`.
- Изменения интерфейса проверять в браузере на `npm start` с временным `DATA_FILE`, включая ширину 375 px
  (без горизонтальной прокрутки).
- Автономный режим проверять по `file://` в настоящем Chrome: headless + Chrome DevTools Protocol
  с флагом `--use-mock-keychain`. Превью встроенного браузера скрипты из `file://` не выполняет.
- В скрытой вкладке браузера таймеры замедляются, и брифинги печатаются медленнее — это особенность
  тестовой среды, а не баг.

## Git и доступы

- Работа в отдельных ветках от `main`, слияние только через Pull Request.
- Коммиты атомарные, Conventional Commits на русском (`feat:`, `fix:`, `docs:`, `refactor:`, `build:`),
  с трейлером `Co-Authored-By` для коммитов от Claude.
- Файлы добавлять поимённо, без `git add -A`: `data/`, `dist/`, `node_modules/` не коммитятся.
  `package-lock.json` коммитится.
- `origin` (`PlexMAD/polytech-quest`) у разработчика может быть только на чтение — тогда изменения
  отправляются в его форк, и оттуда открывается PR.
- **Claude: любые действия с учётными данными — `git push`, форк, PR, команды `gh`, `ssh`, деплой — только
  после явного подтверждения пользователя.** Перед этим сказать, какой ключ или аккаунт будет использован.
  Не переключать remote и способ авторизации молча. Локальные коммиты — без подтверждения.
- Секреты (`ADMIN_KEY`, ключи, токены) не коммитить и не просить вставлять в чат.
